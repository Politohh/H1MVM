# Event-based demo splitter

The Split Demo page has an overview timeline with separate kill, round and bookmark lanes, a paged event list, an event cursor and independent IN/OUT controls. Click an event to select its exact timestamp, then use Set In / Set Out. Click the timeline to position the cursor, drag the green range edges to trim, or adjust the numeric rows. Clicking near a marker snaps to its timestamp. The selected range is shaded; the white line is the event cursor, not a live video preview.

All / Kills / Rounds / Bookmarks filters reuse seven event rows. Events run earliest first, with explicit Time / Killer / Weapon / Victim headings. The green left name is the killer and the right name is the victim; long names are fitted to their column. Weapon icons come from the mapped native weapon's kill icon and retain its aspect ratio. Headshots, melee and environmental deaths use their recorded cause icons when the obituary provides a cause instead of a weapon. Grenade-launcher kills use the 40 mm grenade icon. Missing resident icons fall back to text, never a default checkerboard material. Asset lookups run on the UI thread; file decoding stays on the worker.

Clip controls live in a plain clipped element outside MenuTemplate's automatic vertical list, so decorative backgrounds cannot push controls below the screen. The overview uses 160 bins per lane so long recordings do not create an unbounded number of native widgets. Multiple events can share a bin; individual timestamps remain accessible in the list. Range changes and duplicate save requests are blocked during export. Back navigation runs on the next timer tick after native input dispatch finishes.

Bookmarks toggle at the exact cursor time and are stored in `<recording>.bookmarks.json`, limited to 500 per recording. The recording itself is never edited. Bookmarks belong to that recording; move the sidecar along with it if moving the file. Exported clips retain embedded recorded events but do not copy the original's personal bookmarks.

COD4 inputs are decoded on the library worker when the page first requests events. Kills use the same obituary decoder as conversion, with names from the event's source snapshot. S&D round markers use recorded game-timer configstring 11 transitions: zero to positive is round live; positive to zero is round end. Positive-to-positive changes are not new rounds. The UI identifies these as timer-derived boundaries. Other modes and mods without those transitions do not receive fabricated round markers. Command times have the source decoder's snapshot timestamp precision.

New conversions embed optional `@event2:` kill metadata containing absolute source timestamps, hex-encoded attacker/victim names, the recorded weapon and death cause. Round markers and legacy labels retain `@event:` format. Names are sanitized for control/color codes. The splitter retains these records, and the UI filters them against the clip's actual footer range and rebases to clip-local time. The existing TUI1 kill index and network packets are unchanged. Event annotations share the existing bounded metadata chunk; conversion stops adding annotations at 120,000 bytes or 2,000 total header records. Missing kill annotations fall back to the existing kill index.

Older converted demos automatically recover details from a same-stem `.dm_1` beside the `.dm_h1` file. Recovery requires matching map, POV, time bounds and every indexed kill (including the converter's dynamic client-slot mapping). A mismatched source is rejected. If no verified source is available, indexed kills keep player slot labels and the UI explains how to supply the original. Neither recording is rewritten.

Validation: Release x64 build; native Theater Lua contract suite (plain clipped control container, killfeed columns/icon reuse, filters, marker selection, precise IN/OUT, bookmark toggle, busy guards, deferred Back, constant widget count and timeline clicks); portable splitter tests (rich metadata through nested cuts, unchanged compressed snapshots, invalid input rejection). Verified source/native pairs: City_AKu_1-1__4man (232 kills, 23 round starts, 24 ends) and 6oPuC_3k_r700_backlot (13 kills, two starts, two ends), including rejection of wrong map, POV and victim identities. Resident MWR weapon/cause icon names were inspected read-only. Native visual/runtime results are recorded separately with the preview package.
